# Houdini-Agent 更新记录（2026-10-26）

## 发布摘要

本次更新强化工具执行的安全检查、运行上限和失败恢复，完善自动记忆的试用与引用反馈机制，并为 Plan 澄清、阻塞状态和执行证据增加明确契约。

同时优化按需 Skill 路由与本地帮助检索，补充节点可写性诊断、批量建图校验、几何及视觉完成验证，以及外部 MCP 场景写入说明。

---

## 一、执行安全与失败恢复

- 增加基于 Python AST 的危险导入、调用及文件写入检查，补充导入别名和文件打开模式的识别。
- 加强敏感字段脱敏、危险 Shell 命令匹配和跨用户私有缓存路径检查。
- 同一工具连续两次发生同类执行失败后，暂停本轮继续调用，并提示先检查节点、参数、文档或工具契约。
- 成功获取只读恢复证据后可清除失败计数；线程仍在运行、场景状态未知或执行结果未验证时不会按正常恢复处理。
- 对修改非本会话 Agent 创建节点的操作补充风险信号，并将其纳入确认提示。
- 新增 `config/security_policy.json` 与统一筛查逻辑，对网页、搜索结果和记忆中的疑似指令注入进行拦截；策略不可用时按不可信内容处理。
- 筛查前进行 Unicode 规范化并去除格式控制字符，补充中英文角色伪造、策略绕过和敏感信息外传模式。
- 加强显式记忆、核心记忆召回、用户规则及团队记忆共享的敏感内容和指令注入检查。

## 二、记忆质量策略

- 新增 `config/memory_quality_policy.json`，集中配置试用记忆置信度上限、引用晋升门槛、未使用衰减及规则长度限制。
- 配置敏感内容、控制字符和泛化空洞规则的过滤条件。
- 自动反思和休眠整理产生的规则须有真实 episodic 来源，通过写入检查后进入 `trial`，默认置信度上限为 `0.5`。
- 重复规则合并不再自动增加置信度和激活次数，避免把重复生成误当成有效经验。
- 为注入记忆分配本轮别名，通过回复末尾的 `[mem-used: ...]` 声明结算引用；缺失或非法声明记为未知，不按未引用处理。
- 获得正向 reward 的有效引用增加引用计数；试用规则默认累计三次后晋升为 `active`。已知未引用的规则按策略衰减。
- 内部引用标记从用户可见回复中移除；质量审计采用追加写入，不保存记忆正文。
- 记忆管理器展示近 30 天声明使用率、未引用率、未知轮次及写入决策，标记试用规则，并提示声明引用不等于相关或正确。
- SQLite schema 升级到 v2，增加 `status` 与 `cited_count`；团队导出仅接受满足既有条件的 `active` 规则。

## 三、Plan 澄清、状态与证据

- `ask_question` 校验一至两个问题及选项契约，支持单选、多选和自由文本，提交前要求每题都有有效回答。
- 澄清请求绑定会话和独立请求 ID，区分回答、跳过、超时、停止、界面错误及无效回答；只有 `answered` 产生有效答案，其他状态不代表授权。
- 请求支持停止、切换会话和超时退出；结束后禁用卡片控件，避免过期提交影响后续请求。
- Plan 步骤支持 `blocked`，阻塞或错误状态必须提供原因；界面和执行上下文同步展示阻塞信息。
- 步骤可关联本会话 operation receipt 或持久化工具结果引用，校验引用归属及结果完整性，并返回就绪、阻塞步骤信息。
- 明确区分引用有效、工具执行成功和用户目标验收：步骤标记 `done` 不会自动变成验收通过，界面显示“验收未验证”。
- 质量门失败返回结构化 diagnostics；未知依赖和依赖环仍被拒绝，缺少推荐分组或非首步空依赖作为质量警告处理。
- 分析、布局等非建图任务可省略 architecture，使用步骤 DAG；建图计划只需描述受影响的网络部分，不要求枚举整个场景。

## 四、Agent 运行上限与上下文

- 为流式和 JSON 工具循环提供迭代与工具调用上限，达到上限时返回明确的 `stop_reason` 和用户可见提示。
- 工具调用预算在整轮执行前检查，超预算批次不执行；流式工具消息仍为未执行调用补齐结果，避免产生未配对的工具历史。
- 接近运行上限时提示模型收尾；已执行批次触发中止时保留真实剩余结果，不用未执行占位信息覆盖。
- 后续工具轮次不再回灌 `reasoning_content`，减少模型将最终回答继续放入 thinking 的风险。
- 修复流式循环错误恢复请求的 thinking 状态：启用思考时，恢复请求重新开启 thinking，成功后的普通工具续接仍关闭；用户关闭思考时保持关闭。
- 流式循环的外层临时错误退避支持停止事件打断，保留原有 5/10/15 秒等待和三次重试上限；取消后保留已有正文、工具结果和用量，不再裁剪或发送下一次请求。此改动不覆盖下层 HTTP 重试等待、阻塞网络读取或 Houdini cooking。
- 达到轮数上限后的强制总结继承用户 thinking 设置，并在请求前、流消费和收尾时处理停止信号；取消时保留已有总结片段并返回 `stopped`，不误报成功或追加上限继续提示。

## 五、节点诊断与结果验证

- 节点检查补充锁定 HDA、内部可编辑性、参数锁定及禁用状态，提供最近可编辑祖先等诊断信息。
- 参数写入前检查可写性，返回明确错误分类，避免对不可写目标反复重试。
- 节点错误增加来源归属与代码位置解析，将内部实现节点的 VEX 编译错误关联到可修复的 Wrangle owner 和 `snippet`。
- 批量建图 dry run 返回 `plan_hash`，实际执行可通过 `expected_plan` 检查计划是否变化；失败时补充结构化 `failed_items`。
- 节点 flag 写入扩展回读验证，回读不一致或无法读取时保留期望值、实际值及原因，而不只返回未知状态。
- 主线程 operation receipt 增加截断后的 `error_detail`；诊断导出汇总调用成功率、按工具和错误码的失败分布、近期错误及策略动作。
- 完成验证优先复用最后一次场景修改后的新鲜技术证据，避免重复读取基础几何计数；Manual 或新鲜度未知时才要求临时 Auto 验证，并确认原始模式恢复。
- 对视口可见结果要求最终 `visual_review`；技术工具成功或单独保存截图不能替代模型视觉审查，证据不足时保持 `inconclusive`。
- QC 失败后按原检查范围进入故障排查和复验，不默认重跑所有检查，也不把指导文本当作场景验收证据。

## 十、声明式工具治理与审计降级

- 将工具模式白名单、风险覆盖、确认规则、调用频率和危险参数模式统一迁移到 `config/security_policy.json`，Tool Registry、Harness 与内容安全检查共享同一份不可变策略快照。
- 策略结构非法、正则无效、引用未知工具或策略文件不可用时统一 fail closed；只读工具也不会在无有效策略的情况下继续执行。
- 声明式参数规则可直接控制 Harness 的允许、确认或拒绝决策，风险覆盖同步进入工具元数据和界面展示，不再依赖分散的硬编码集合。
- 工具执行审计增加 run、call、策略版本、匹配规则、风险分数和最终结果等关联字段，不记录用户提示正文。
- 外部 MCP 调用继续采用最严格策略组合；外部进程任务在审计写入失败后进入 degraded 状态，禁止启动新进程，并将已有任务标记为不可安全重放。
- 补充两份 ADR，记录外部 MCP 治理边界，以及 Prompt、Tool Contract 与 Skill 的职责归属。

## 十一、请求级工具暴露与续轮契约

- 工具 schema 改为按当前模式和请求上下文选择，不再把上一请求的工具集合跨请求粘滞复用。
- Native tool discovery 在当前模型响应结束后才刷新下一轮 schema，避免模型在同一响应中调用尚未实际暴露的工具。
- 请求组装集中保留工具结果恢复所需的 `result_ref`、分页指针、偏移量和 `content_omitted` 信号，同时过滤不应回传 provider 的内部字段。
- 工具说明区在续轮中保持单份，新增发现的工具可进入下一请求，不重复注入整套可用工具文本。
- Thinking 续轮继续按工具类别选择轻量或深度提示，并保持用户关闭 thinking 时不被内部恢复路径重新开启。

## 十二、记忆写入与反馈结算收紧

- 试用记忆只有在被有效引用、任务明确成功且 reward 达到配置门槛时才累计晋升证据；低 reward 或成功状态未知不再推动晋升。
- 被引用但导致失败或负向 reward 的规则按独立衰减系数降低置信度，惩罚强于单纯未使用，且保留不同抽象层级的最低置信度边界。
- 自动规则写入复用统一的记忆威胁检测，拒绝提示注入、凭据、私钥和控制内容；审计只记录拒绝原因，不保存规则正文。
- 增加可配置的泛化规则正则，过滤“始终遵循最佳实践”“认真思考”等缺乏可执行技术信息的中英文变体，同时保留具体、可验证的技术建议。
- 质量策略为旧配置补充晋升 reward 门槛、负向引用衰减和泛化模式默认值，并在加载时校验数值范围及正则有效性。
