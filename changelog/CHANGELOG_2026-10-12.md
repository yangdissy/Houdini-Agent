# Houdini-Agent 更新记录（2026-10-10 至 2026-10-12）

## 发布摘要

本次更新主要收紧用户 Skill 的安装与启用边界，增强 Houdini 主线程超时后的阻断和审计信息，并继续完善文档检索缓存、团队记忆隔离与诊断可观测性。

用户 Skill 现在使用持久化激活清单：已有用户目录可平滑迁移，新安装文件不会仅因出现在目录中就自动获得执行资格。预览仍保持只读，安装或激活动作必须经过独立确认。

Houdini 主线程工具超时后会明确标记后台执行可能仍未结束、场景一致性未知，并阻止后续工具继续进入同一执行通道，避免将超时误判为操作已停止。

---

## 一、用户 Skill 激活治理

- 用户 Skill 目录新增 `.active_skills.json` 持久化激活清单，loader 只加载清单中明确启用的 Skill。
- 兼容已有用户：首次发现目录中已有 Skill 且尚无清单时，将现有文件迁移为已激活状态并写入清单。
- 清单已经存在后，新出现的 Python 文件不会自动激活，避免仅通过文件落地绕过安装与确认流程。
- 激活清单损坏或格式非法时 fail closed，不回退为加载目录内全部文件。
- loader 校验授权文件名与 `SKILL_INFO.name` 一致，拒绝通过元数据名称冒充其他已授权 Skill。
- 用户 Skill 导入或契约校验失败时记录结构化诊断，包括文件、阶段、错误码和消息。
- 每个用户继续使用独立的 `cache/users/<username>/skills` 目录，并在用户配置中持久化 `user_skill_dir`。

---

## 二、Skill 安装与确认边界

- `install_houdini_skill` 的 `preview` 保持无写入行为，不因通用 Step Confirm 设置产生多余确认。
- `install` 与 `activate` 被识别为受控写入动作，在 Agent 和 Plan 模式下必须显式确认。
- 控制动作从 Skill 参数中的 `action` 或 `mode` 解析；缺省行为仍按 `preview` 处理。
- `/create_skill` 被纳入带参数的 slash command，创建请求继续只生成草案，不直接写入或执行代码。
- 工具选择指南补充 Skill 草案、预览、安装和独立行为测试的推荐流程。

---

## 三、Houdini 主线程超时与场景一致性

- 单工具或批量主线程执行超时后，结果新增 `thread_still_running: true`。
- 超时结果新增 `scene_consistency: unknown`，明确表示无法证明场景是否已完成或部分完成修改。
- 执行器在超时后进入阻断状态，拒绝继续接受后续工具，防止与仍可能运行的 Houdini 操作并发交错。
- executor shutdown 后拒绝新执行，避免面板关闭期间继续派发场景操作。
- 超时、阻断、关闭以及迟到结果均进入受限事件记录；事件不包含工具原始参数或敏感值。
- Harness 审计记录同步包含 `thread_still_running` 和 `scene_consistency`，便于诊断操作是否可能仍在后台影响场景。

---

## 四、执行审计与治理增强

- `execute_python` 的起始审计仅记录代码 SHA-256 摘要，不记录原始代码正文。
- 受控 Skill 写入动作使用独立风险因子和确认理由，避免与普通只读 Skill 混为同一风险路径。
- 外部 operation 继续记录阶段、退出码、产物和单调进度，并保持 session 隔离。
- 诊断导出扩展主线程执行器、外部作业和 Skill loader 的结构化状态，同时避免导出 prompt、payload、绝对路径或代码正文。

---

## 五、文档检索与缓存

- Houdini 离线帮助的页面读取、搜索与索引继续共用同一过滤、解码和大小限制规则。
- 文档语义向量缓存增加模型来源校验，避免复用由不同 backend、model、dimension 或格式版本生成的旧缓存。
- 缓存不可用、损坏或与当前模型不兼容时重新编码，不把不同语义空间的向量混入排序。
- 多语言语义搜索仍只在真实 Sentence Transformers 后端启用；模型失败时回退词法检索。
- Copernicus OpenCL 参考资料加入本地文档源，补充 Kernel、绑定、采样和边界处理等检索证据。

---

## 六、个人与团队记忆隔离

- 团队记忆 store 按当前用户名获取，避免长生命周期面板在用户切换后继续复用其他用户的 store 实例。
- 团队记忆数据库增加当前 embedding 来源信息；来源不兼容时暂停语义评分，不比较不同模型空间中的向量。
- 团队记忆重建继续使用当前模型统一重算向量后再去重，并保留 contributor 合并和质量过滤规则。
- 记忆迁移提示在主线程显示，向量迁移在后台执行；成功和失败均使用独立对话框反馈。
- 团队导出设置针对网络盘替换失败增加回退路径，避免开关更新被静默丢弃。

---

## 七、测试与验证

- 用户 Skill 激活测试覆盖首次迁移、新文件默认不激活、损坏清单 fail closed、名称不匹配拒绝和结构化加载诊断。
- 主线程执行器测试覆盖超时阻断、shutdown 拒绝、迟到结果、敏感参数不进入事件日志，以及场景一致性状态传播。
- Harness 测试覆盖受控 Skill 的 preview、install、activate 确认差异和 Python 代码摘要审计。
- 文档检索测试覆盖统一帮助源、页面过滤、跨语言语义召回和 embedding 缓存兼容性。
- 团队记忆测试覆盖当前模型重编码、用户隔离、向量来源不兼容处理和网络盘设置写入回退。

---

## 已知范围

- 用户 Skill 激活清单只控制 loader 加载资格，不替代源码审查、聚焦测试和运行时风险确认。
- 主线程执行超时无法强制终止已经进入 Houdini 的调用；因此执行器选择阻断后续操作，并将场景一致性标记为未知。
- 文档向量缓存与具体 embedding 模型绑定；模型切换后首次搜索需要重新编码，延迟会高于后续查询。
- 团队记忆语义搜索在 embedding 来源不兼容时暂停，需要使用当前模型重建数据库后恢复。
- Copernicus OpenCL 资料用于离线检索和解释，不会编译或执行用户 Kernel。
