# Houdini-Agent 更新记录（2026-08-19～2026-08-24）

## 发布摘要

本次更新聚焦记忆系统的可控性、可恢复性与用户反馈闭环：新增显式核心记忆命令和长期记忆管理界面，修复历史记忆数据库路径及恢复问题，为 `remember_memory` 增加明确意图校验与写入前确认，并允许用户通过“有用 / 有问题”直接强化或削弱任务经验。

本次同时整理了斜杠命令解析和输入补全链路。未新增运行时依赖。

---

## 一、显式核心记忆

### 改动

- 新增 `/remember <内容>`，允许用户把明确偏好或规则直接写入 L0 核心记忆。
- `/memory` 增强为记忆系统状态入口，可查看长期记忆统计与核心记忆。
- 新增 `/memories`，打开长期记忆管理窗口。
- `remember_memory` 工具描述补充“记住上面的回答或对话”等使用场景，提高模型选中正确工具的概率。
- 重复内容不再重复写入；返回 `already_exists` 时会附带已有记忆摘要和记忆 ID。
- 显式记忆操作写入独立审计记录；审计写盘失败会输出告警，不再静默忽略。

### 意图安全

- `remember_memory` 只接受用户本轮明确提出的保存请求。
- 新增中英文否定语义守卫，例如“不用记住”“不要保存”“do not remember”不会被误判为保存意图。
- Ask 模式仍禁止写入长期记忆。
- 每个 Agent 请求最多调用一次 `remember_memory`，避免重复保存与重复确认。

---

## 二、长期记忆写入前确认

### 改动

- `remember_memory` 通过显式意图校验后，由 Harness 返回 `ask`，不再直接写入。
- 确认卡片展示模型总结出的完整记忆内容，取消原有 120 字符截断。
- 用户确认后才执行写入；取消、确认超时或确认回调异常均 fail closed。
- 即使处于 Direct Execute，显式长期记忆仍必须人工确认。

### Bug 修复

修复用户输入“记住上面这次的回答”后确认卡片偶尔不弹出的问题。

根因是本轮用户消息曾在线程内从可变会话历史反查，Harness 可能获得上一轮消息，从而错误判定为缺少显式保存意图。现在改为：

- 在发送边界立即捕获本轮原始用户文本。
- 将文本快照放入 Agent 后台线程参数。
- Harness 始终使用本轮快照进行意图判断。
- Plan 执行阶段同步传递对应消息快照。
- 删除调试期间会打印用户消息内容的临时探针。

## 三、人工反馈与经验奖惩

### 改动

- 对执行过工具的 Agent 回答新增“有用 / 有问题”反馈按钮。
- 任务反思写入 episodic memory 后，将其 ID 绑定到对应回复卡片。
- 如果用户先点击反馈、episodic memory 稍后才完成写入，反馈会暂存并在绑定后补应用。
- “有用”将 reward 调整为 `0.85`，强化记忆并添加 `user_praised` 标签。
- “有问题”将 reward 调整为 `0.15`，衰减记忆并添加 `user_rejected` 标签。
- 用户反馈直接修改奖励状态，不额外调用 LLM，也不触发新一轮反思。

### 用户影响

- 用户可以明确告诉系统哪些任务经验值得保留，哪些经验不应继续强化。
- 反馈成本低、立即生效，同时保留后续分析所需的标签。

## 四、记忆管理界面

### 改动

- 新增长期记忆管理窗口，统一管理 episodic、semantic 和 procedural memory。
- 支持查看、筛选、编辑和删除记忆记录。
- semantic memory 可查看和调整类别、置信度、抽象层级、激活状态及关联 episodes。
- episodic memory 可查看任务、总结、指标和 actions。
- procedural memory 可查看和编辑策略信息。
- 危险操作采用独立确认 sheet，降低误删风险。
- 增加对应中英文文案与 QSS 样式。

---

## 五、记忆数据库路径与恢复

### 权威路径

- 用户个人记忆数据库统一存储在 `cache/users/<username>/memory/agent_memory.db`。
- 旧 LocalAppData 路径只作为历史残留数据库的恢复来源，不再作为实时权威库。
- 普通 legacy 文件迁移会跳过 SQLite 主库、WAL 和 SHM，避免把数据库工件当作普通缓存文件复制。

### 自动恢复

- 启动时检查历史残留数据库，使用只读 `quick_check`、记录数和 ID 指纹判断可恢复性。
- 权威库为空且残留库有效时，通过 SQLite backup API 生成完整快照并原子发布。
- 权威库与残留库内容等价时不重复恢复。
- 两边都含有不同用户记录时停止自动处理并报告冲突，不做不安全自动合并。
- 恢复结果写入用户级标记，防止每次启动重复提示。

### 冲突处理

- 用户可选择保留权威库并清理历史残留库。
- 用户确认以残留库覆盖权威库时，会先备份现有权威库为 `agent_memory.db.pre-overwrite-backup`。
- 覆盖通过 SQLite backup 合并 WAL 中的最新数据，并在发布前执行完整性检查。
- 恢复或覆盖任一步骤失败时保留原有数据，避免静默数据丢失。

## 六、斜杠命令与输入体验

### 改动

- 斜杠命令解析提取到独立纯 Python 模块，便于统一测试和复用。
- 输入框新增分类命令补全，记忆相关命令集中展示。
- 带参数命令从补全列表选中后保留输入焦点，便于继续填写内容。
- 未知命令、缺失参数和执行错误提供明确反馈。

---

## 七、兼容性与安全边界

- 无新增运行时依赖。
- 保持现有 episodic、semantic、procedural memory 数据结构兼容。
- 保持现有 Team Memory 隐私边界不变。
- `remember_memory` 的人工确认属于强制治理边界，不被普通确认开关绕过。
- 策略异常、确认异常和数据库恢复歧义均按 fail-closed 处理。
- 审计记录不保存完整用户 prompt；临时用户消息诊断输出已经删除。

## 八、测试与验证

### 新增或更新覆盖

- 显式保存意图与中英文否定语义。
- 重复核心记忆和审计失败行为。
- `remember_memory` 的 intent、Ask mode、人工确认和单请求一次限制。
- 发送边界用户消息快照，防止上一轮消息进入 Harness。
- Agent 工具选择与 Tool Registry metadata。
- episodic feedback 的正向强化、负向衰减、标签与延迟绑定。
- 记忆数据库恢复、冲突、覆盖备份、SQLite 工件过滤和恢复标记。
- 用户记忆权威路径与旧路径隔离。
- 斜杠命令解析和参数规则。

### 当前验证结果

- `remember_memory` 确认卡片已在 Houdini 宿主中实际验证成功。
- 最近一次记忆/Harness/反馈聚焦回归：54 tests passed。
- 相关生产文件与测试文件未发现 VS Code 诊断或 Python 语法错误。

## 已知范围

- 当前“有用 / 有问题”仅对执行过工具并产生 episodic memory 的 Agent 回复显示，这是有意保留的范围。
- 人工反馈只修正奖励和标签，不自动触发 LLM 反思；负向反馈原因收集与二次反思尚未实现。
- 记忆数据库冲突不做自动记录级合并，必须由用户选择保留哪一份，以避免不可逆的数据污染。
