# Houdini-Agent 更新记录（2026-08-25）

## 发布摘要

本次更新聚焦 Team Memory 导入边界、显式长期记忆可靠性、上下文压缩一致性与界面可用性：团队导出文件在进入共享库前统一经过版本化文档解析、资源限制、向量元数据校验和共享资格过滤；显式记忆链路补强本轮用户意图传递与确认失败可观测性；自动上下文裁剪开始真正遵循用户选择的压缩策略；同时修复记忆管理器布局和规则来源路径显示问题。

本次不提升版本号，当前版本仍为 `1.5.3`；未新增运行时依赖，也不要求迁移现有配置。

---

## 一、Team Memory 导出文档与信任边界

### 改动

- 新增版本化 Team Memory 导出文档，当前 schema version 为 `1`，并继续兼容 legacy v0 文档。
- 导出文档携带成员身份、导出时间、semantic、procedural 及 embedding provenance；重建时验证扫描来源成员与文档声明身份一致。
- 统一导出端与导入端的共享资格策略，避免两端对类别、抽象层级、置信度、使用次数和成功率采用不同规则。
- 导入前校验文档结构、集合类型、条目数量、文本长度、文件大小、有限数值、向量维度及 embedding format version。
- 明确区分两类过滤结果：结构或安全无效的 `invalid entry`，以及结构合法但不满足共享资格的 `ineligible entry`。
- 无效条目诊断只记录成员、条目类型、原因与索引，不记录记忆正文。
- 单次解析最多保留 100 条诊断，避免恶意或损坏文档制造无界日志。

### 重建语义

- 发现导出文件但全部文档无效时，重建失败并保留现有 live database，不再用空库覆盖可用团队记忆。
- 确实不存在成员导出文件时，会发布一个空团队记忆库，以清理已撤回的历史共享内容。
- 重建统计新增有效文档数、无效条目数、不合共享资格条目数、资格过滤原因和有限诊断。
- 管理员从菜单重建后可直接看到扫描人数、合并数量、拒绝文件、无效条目与资格过滤数量。

### 用户影响

- Team Memory 不再直接信任共享目录中的任意 JSON 内容。
- 损坏、超限、身份不匹配或向量不一致的导出不会污染现有团队记忆库。
- 成员删除或撤回全部导出后，管理员重建可正确清空旧团队记忆。

## 二、显式长期记忆可靠性

### 改动

- `remember_memory` 的 Harness 决策始终使用发送边界捕获的本轮原始用户文本，不再从可变会话历史反查意图。
- Plan 执行阶段同样显式传递对应用户消息，避免计划确认后的记忆写入丢失原始意图。
- 每次请求开始时重置 `remember_memory` 调用计数，并继续限制单请求最多调用一次。
- 工具确认超时会输出明确日志；确认回调异常会记录 traceback，最终仍按未确认处理。
- L0 核心记忆加载上限由 5 条提高到 8 条，并明确用户手动设置的核心记忆优先于自动积累经验。
- 系统规则补充显式记忆约束：仅在用户明确要求保存时调用，成功前不得宣称已保存，且禁止保存密码、API key 或 token。

### 安全边界

- 普通问答和“你还记得吗”仍不能触发长期记忆写入。
- Ask 模式继续禁止写入长期记忆。
- 通过意图检查后仍必须展示待保存内容并取得人工确认。
- 确认超时、确认异常或写入失败均 fail closed。

## 三、上下文压缩策略一致性

### 改动

- 新增统一的自动裁剪策略参数，由 `Aggressive`、`Balanced`、`Conservative` 分别控制目标上下文占用率和近期轮次保护比例。
- 普通发送、主动压缩和超预算恢复路径统一使用当前压缩策略，不再硬编码 60% 保护比例与 65%/70% 目标比例。
- 压缩策略菜单改为互斥选择，切换后同时更新 UI 状态与 `TokenBudget` 的实际策略。
- Aggressive 会保留更少近期轮次并压到更低占用；Conservative 会保留更多轮次并采用更宽松目标。

### 用户影响

- 用户选择的压缩策略现在同时影响手动压缩和自动裁剪行为。
- 同一策略在正常发送与上下文超限恢复中的表现更一致、可预测。

## 四、界面与交互修复

### 记忆管理器

- 修复 episodic、semantic、procedural 三个页面引用错误布局变量导致初始化失败的问题。
- 列表工具栏、筛选框和列表现在正确加入各自布局。

### Rules 编辑器

- 内置用户规则也显示实际磁盘来源路径，不再只对文件型规则显示来源。
- 长路径使用中间省略的单行标签展示，完整路径保留在 tooltip 中并可用鼠标选择。

### 菜单与命令

- 顶部溢出菜单将 `Cache`、`Optimize` 调整为“缓存设置”“上下文压缩”。
- 尚未开放的训练数据导出与 Update 菜单项改为禁用，避免用户点击后误以为功能已执行。
- `gpt-5.5` 的上下文上限更新为 425,000 tokens。
- 带参数斜杠命令从补全列表选中后保留输入内容和焦点；`/remember` 继续使用专用引导交互。

---

## 五、工具分类与执行语义

- Tool Registry 新增 `memory_write` 能力分类，将 `remember_memory` 与普通记忆检索意图区分。
- `remember_memory` 保持非并发安全、normal risk，并明确不允许 Ask mode。
- 工具必需参数表新增 `remember_memory.content`，缺少内容时在执行前拒绝。
- Tool schema 强化“记住上面的回答或对话”场景描述，同时要求先提炼待保存内容。
- 人工反馈继续直接调整 episodic reward、importance 与 `user_praised` / `user_rejected` 标签，不额外调用 LLM。

---

## 六、兼容性与安全

- 当前版本保持 `1.5.3`。
- 无新增运行时依赖。
- Team Memory 继续读取 legacy v0 导出；新导出统一使用 schema v1。
- 个人记忆与 Team Memory embedding format version 保持统一。
- Team Memory 文档校验、显式记忆意图检查和人工确认异常均采用 fail-closed 行为。
- 审计与导入诊断不记录完整用户 prompt 或记忆正文。

## 已知范围

- Team Memory v1 校验的是导出文档及条目结构，不提供文档签名或来源加密认证；成员身份仍由受控扫描路径与文档声明一致性共同约束。
- Team Memory 仍采用整库重建，不执行跨成员导出文件的增量事务合并。
- `forget` 与 `search_mem` 暂不在斜杠补全列表显示，但解析层仍保留带参数命令定义。
- 训练数据导出与 Update 菜单项本次仅禁用，未删除底层入口。
