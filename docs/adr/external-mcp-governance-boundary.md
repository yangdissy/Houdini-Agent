# External MCP Governance Boundary

Date: 2026-09-24

## Status

Accepted and implemented.

## Legacy Surface

Before migration, the external FastMCP server owned a parallel decorator-based
tool surface. It included health and direct Houdini operations, called `hou` or
`hou_core` without Registry/Harness authorization, and exposed arbitrary Python
execution as `execute_python_code`. Its schemas and behavior were independent of
`HOUDINI_TOOLS` and `MCPClient._TOOL_DISPATCH`.

The legacy bypass is now represented by a regression contract: production
server source must not contain the old registration function, arbitrary Python
tool, or direct `hou_core` dispatch. Executable schemas are derived from
external-visible Registry entries and the committed capability manifest.

## Adapter Contract

Input consists of server-owned `ExternalMCPContext`, a Registry tool name, and
untrusted arguments. The trusted context contains:

- Session ID owned by the current Houdini Agent session.
- Fixed external client ID.
- Mode selected by the server, currently `ask` for FastMCP wrappers.
- Username inherited from the owning Houdini Agent UI session.
- Per-call correlation ID generated by the adapter.

The adapter validates context completeness, explicit allowlist and deny list,
Registry mode/runtime authorization, risk limits, session call limits, and
concurrency limits before invoking the shared `GovernedToolExecutor`.

Output is the same structured tool result used by internal execution. Audit
records include policy decisions, result category, trusted identity metadata,
and correlation ID. They do not include prompts or argument values.

## Human Confirmation

Policy action `ask` requires an injected confirmation callback. If no callback
exists, it raises, or the user declines, execution is denied. External MCP has
no implicit allow fallback. Tools that cannot safely operate without a reliable
confirmation channel remain absent from the external-visible Registry surface.

## Thread Boundary

FastMCP wrappers do not call Houdini handlers directly. Authorized Houdini
tools reuse the existing internal dispatch function, which enters
`HoudiniMainThreadExecutor`. Local-runtime tools are not granted additional
permissions by this adapter.

## Error Model

Governance configuration, Registry checks, policy decisions, executor state,
and feature detection fail closed. Results and exceptions pass through the
shared result guardrail and sanitization path. Runtime capabilities hide tools
whose handler, optional module, or required Houdini version is unavailable.

## Shutdown

Stopping the server permanently closes its adapter before waiting for the HTTP
thread. Closed adapters reject new calls, including calls through wrappers that
were captured before shutdown. A blocked, shut down, or unreadable main-thread
executor also rejects calls before policy or handler dispatch. Restart requires
a newly configured adapter; a stopped adapter cannot be reused.

## Consequences

- Tool Registry remains the schema and execution-semantics authority.
- Harness remains the policy, confirmation, retry, result, and audit authority.
- FastMCP is only a transport adapter.
- No external path reaches arbitrary Python, shell, direct `hou`, or `hou_core`.
- Domain readers for geometry, USD, and PDG share the same internal handlers as
  the embedded Agent and remain read-only and bounded.
